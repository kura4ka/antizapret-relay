# AntiZapret Relay

Собственный VPS вместо Cloudflare WARP в [GubernievS/AntiZapret-VPN](https://github.com/GubernievS/AntiZapret-VPN).

Например: клиент подключён к AntiZapret в Японии, а `old.yummyani.me` выходит в Интернет с IP вашего VPS в Германии. Используется штатная маршрутизация доменов AntiZapret; клиентские VPN-профили менять не нужно.

```text
Клиент → AntiZapret JP → WireGuard → VPS DE → выбранный сайт
                     ↘ обычный выход для остальных сайтов
```

Целевые системы: Debian 13 на входном VPS и Ubuntu 24.04 на выходном. Оба сервера могут иметь уже установленный AntiZapret. Выходному VPS достаточно обычного Linux с systemd. Установка требует root и работающего WireGuard в ядре. Это первая версия; проверки перечислены ниже, испытание на двух реальных VPS ещё требуется.

## Установка

Скачайте `install.sh` из этого репозитория **на оба VPS**. Скрипт автономный: вспомогательные файлы проекта на сервер копировать не нужно. Запускайте сохранённый файл через `bash`, а не через `sh`.

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
```

На **сервере в Германии**:

```bash
sudo bash install.sh server --endpoint GERMANY_PUBLIC_IPV4
```

Замените `GERMANY_PUBLIC_IPV4` реальным публичным IPv4 Германии. По умолчанию используется UDP-порт **51888** и отдельная подсеть `10.203.240.0/24`. При необходимости:

```bash
sudo bash install.sh server --endpoint GERMANY_PUBLIC_IPV4 --port 51888 --uplink eth0 --subnet 10.203.241.0/24
```

Откройте выбранный UDP-порт в сетевом firewall панели хостинга. Скрипт добавит необходимые правила на самом Linux-сервере. Он создаст `/root/antizapret-relay-client.json` с правами `600`. В этом файле **приватные ключи**: передавайте его только между своими серверами, не публикуйте в GitHub и не вставляйте в чат.

Скопируйте файл **из Германии в Японию** через SSH, например из root-сессии в Германии:

```bash
scp /root/antizapret-relay-client.json root@JAPAN_PUBLIC_IPV4:/root/
```

На **сервере в Японии**:

```bash
sudo bash install.sh client \
  --bundle /root/antizapret-relay-client.json \
  --domain old.yummyani.me
```

AntiZapret кратковременно перезапустится; активные соединения могут прерваться. Установщик заменит удалённые peers для штатных `warp-antizapret` и `warp-vpn` и установит согласованный MTU 1280. Режимы станут `ANTIZAPRET_WARP=4` и `VPN_WARP=3`: через Германию пойдут домены группы WARP, а не весь VPN-трафик. Если обычный полный VPN менять не нужно:

```bash
sudo bash install.sh client --bundle /root/antizapret-relay-client.json \
  --antizapret-only --domain old.yummyani.me
```

После настройки сохраните JSON в защищённом месте либо удалите его с обоих VPS. Рабочие ключи уже записаны в конфигурацию туннелей.

## Домены

В Японии:

```bash
sudo antizapret-relay domain add old.yummyani.me
sudo antizapret-relay domain add https://old.yummyani.me/
sudo antizapret-relay domain list
sudo antizapret-relay domain remove old.yummyani.me
```

Собственный список: `/root/antizapret/config/relay-include-warp-hosts.txt`. Домен включает все свои поддомены. Команда сразу запускает штатный `parse.sh`; после изменения очистите DNS-кеш устройства или переподключите VPN. Прямое редактирование списка тоже поддерживается, после него выполните `/root/antizapret/parse.sh`.

**Это замена существующего WARP.** Через Германию пойдут также домены из остальных штатных `config/*include-warp-hosts.txt` и `download/*include-warp-hosts.txt`. Это не независимая третья группа рядом с Cloudflare. Штатные `exclude-warp-hosts.txt` сохраняют приоритет исключения; удаление из списка relay не убирает домен из других списков. Если сайт загружает видео, изображения или авторизацию с других доменов, их потребуется добавить отдельно.

## Проверка

На обоих серверах:

```bash
sudo antizapret-relay status
```

В Японии `wg show warp-antizapret` должен показывать endpoint Германии, недавний `latest handshake` и счётчики передачи. В Германии `wg show az-relay` показывает два отдельных peers. Наличие интерфейса само по себе не подтверждает связь.

Проверка таблиц маршрутизации в Японии:

```bash
ip -4 rule show
ip -4 route show table 1000
ip -4 route show table 2000
```

В таблицах должен быть `default dev warp-antizapret` и `default dev warp-vpn` соответственно. Для `--antizapret-only` модуль управляет только таблицей 1000. Затем проверьте сайт с **подключённого VPN-клиента** и увеличение RX/TX peers. Обычный `curl https://old.yummyani.me` на самом японском VPS не проверяет доменную маршрутизацию клиентов. Установщик не меняет основную таблицу и маршрут SSH.

## Восстановление

```bash
sudo antizapret-relay uninstall
```

На клиентском VPS восстанавливаются только изменённые параметры WARP, остальные текущие настройки AntiZapret сохраняются. Удаляется собственный список relay. Если управляемые параметры были вручную изменены после установки, восстановление остановится, сохранив резервную копию в `/etc/antizapret-relay`. На выходном VPS удаляются только интерфейс relay и его правила.

Обычное ежедневное обновление AntiZapret сохраняет настройки. Полная переустановка его `setup.sh` пересоздаёт `/root/antizapret`: после неё потребуется повторная настройка relay. Не запускайте такую переустановку поверх установленного модуля без сохранения ключей и удаления модуля.

## Ограничения

- Cloudflare WARP и relay используют одну штатную группу доменов. Несколько выходных стран и автоматическое переключение между ними здесь не реализованы.
- DNS-настройки остаются существующими: модуль не переносит DNS-запросы в Германию. DNS-фильтрация, CDN, cookies и геопроверки сайта могут требовать отдельной диагностики.
- Нужен DNS AntiZapret; браузерный DoH и обходной DNS могут обойти выбор домена. Сохраняются штатные ограничения AntiZapret на IPv6 и HTTPS/SVCB.
- Дополнительные правила запрещают помеченному трафику выход через другой интерфейс при исчезновении туннеля. При недоступной Германии выбранные сайты перестают открываться; автоматического резервного выхода нет.
- Выходной сервер разрешает peers только выход в публичный IPv4 Интернет, ограничивает доступ к локальной сети и самому VPS. Стандартный firewall AntiZapret может блокировать адрес источника в таблице `raw`; такие запреты сохраняются.
- Выходной IP VPS может сам блокироваться конкретным сайтом. Выбор Германии сам по себе не гарантирует доступность сайта.

## Разработка и проверки

Исходники установщика находятся в `lib/`; готовый `install.sh` собирается без внешних библиотек:

```bash
python3 tools/build.py
python3 -m unittest discover -s tests -v
bash -n install.sh
```

Тесты проверяют безопасное чтение bundle, валидацию доменов, изменение и восстановление настроек, а также правила выходного firewall через подставной `iptables`. Они не заменяют сетевой тест на реальных VPS. Подробности интеграции и проверенный upstream-коммит: [docs/architecture.md](docs/architecture.md).
