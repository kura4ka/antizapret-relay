# AntiZapret Relay

Модуль для [AntiZapret-VPN](https://github.com/GubernievS/AntiZapret-VPN): Ваш VPS вместо Cloudflare WARP.

Используется штатная маршрутизация AntiZapret в режиме **Custom**: домены задаются в `config/include-warp-hosts.txt`, исключения — в `config/exclude-warp-hosts.txt`. Модуль подключает ваш донорский VPS вместо Cloudflare; списки обрабатывает сам AntiZapret. Названия WARP в его настройках сохраняются.

Поддерживаются Debian/Ubuntu с systemd и WireGuard; целевые версии — Debian 13 и Ubuntu 24.04.

Все команды выполняйте по SSH **под root**. Если вошли другим пользователем, сначала выполните `sudo -i`.

## На доноре

Скачайте и запустите установщик:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh
```

В меню выберите **`2` — Server / donor**. Затем укажите:

- **Публичный IPv4 этого VPS** — IP, через который должны открываться выбранные сайты.
- **UDP-порт** — нажмите Enter для `51888` или введите свой.

В панели хостинга откройте выбранный **UDP-порт**. На самом VPS правила firewall скрипт добавит автоматически. Подсеть и ключи создаются автоматически.

Донор готов. Перейдите к клиентскому VPS; домены на доноре настраивать не нужно.

## На клиенте

Подключитесь по SSH **к VPS с работающим AntiZapret**, скачайте и запустите тот же установщик:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh
```

### 1. Подключите донора

В меню выберите **`1` — Client**. Укажите **публичный IPv4 донорского VPS** и его **SSH-порт** — обычно `22`. Если на клиенте уже есть `/root/antizapret-relay-import.json`, мастер автоматически использует этот файл и пропустит запросы IP и SSH-порта.

При подключении по IP мастер получит настройки через `scp` от имени `root` на доноре. Если SSH запросит пароль, введите пароль root **донорского VPS**. При подключении по SSH-ключу используется настроенный ключ; при первом соединении проверьте отпечаток хоста.

UDP-порт туннеля и ключи передаются автоматически. Если файл подключения уже скопирован на клиент, можно использовать его без SSH к донору — см. [ручную передачу настроек](#ручная-передача-настроек). AntiZapret кратковременно перезапустится.

При установке клиентской роли все домены из встроенных `download/*include-warp-hosts.txt` автоматически исключаются из выхода через донора. Недостающие записи добавляются в блок `ANTIZAPRET RELAY DEFAULT WARP EXCLUSIONS` в `/root/antizapret/config/exclude-warp-hosts.txt`; уже имеющиеся исключения сохраняются на своих местах. Поэтому встроенные домены Cloudflare и STUN/TURN не начинают использовать донора автоматически. Ваши include-файлы сохраняются.

Мастер также спросит **`Route Gemini through the donor? [y/N]:`**. Ответьте `y`, чтобы добавить в штатный `/root/antizapret/config/include-warp-hosts.txt` расширенный набор из [47 доменов для Gemini](docs/gemini-domains.txt). С версии `0.3.3` он включает предоставленный список адресов приложения, API, входа и загрузки ресурсов.

В набор входят родительские домены `googleapis.com`, `googleusercontent.com` и `gstatic.com`. По правилам AntiZapret через донора будут направляться также их поддомены, используемые другими сервисами.

Изменения применяются автоматически. Enter или `n` пропускает добавление и сохраняет уже имеющиеся записи. В режиме только донора или при отложенной клиентской роли этого вопроса нет.

### 2. Укажите домены в штатных списках AntiZapret

Всё выполняется **на клиентском VPS**. Откройте файл `/root/antizapret/config/include-warp-hosts.txt` в любом текстовом редакторе и добавьте нужные домены — по одному на строку:

```text
example.com
example.org
```

Если домен нужно исключить из маршрута через донора, добавьте его в `/root/antizapret/config/exclude-warp-hosts.txt`. Например, чтобы исключить один из поддоменов `example.com`:

```text
direct.example.com
```

Указывайте домены без `https://`, пути и `*`. Запись включает сам домен и его поддомены. Исключённые домены обрабатываются по остальным правилам AntiZapret.

После изменения любого из этих файлов примените списки **на клиентском VPS**:

```bash
/root/antizapret/parse.sh
```

В дальнейшем добавляйте и удаляйте домены в этих же файлах и снова запускайте `parse.sh`. На доноре списки доменов настраивать не нужно. Если видео, изображения или авторизация загружаются с других доменов, добавьте их отдельно.

**Учитываются все штатные списки WARP**, включая другие `config/*include-warp-hosts.txt`. Исключения из `config/*exclude-warp-hosts.txt` продолжают действовать. Чтобы исключить домен, который присутствует в другом include-файле, внесите его в `exclude-warp-hosts.txt`.

Если хотите направить через донора один из автоматически исключённых доменов, удалите его строку из блока `ANTIZAPRET RELAY DEFAULT WARP EXCLUSIONS` в `exclude-warp-hosts.txt`. Проверьте также исключения для родительского домена и примените `parse.sh`. Простое добавление домена в include-файл не отменяет исключение.

Чтобы добавить расширенный набор Gemini на уже установленном клиенте, выполните **на клиентском VPS**:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh preset gemini
```

Команда дополнит прежний набор недостающими доменами без переустановки клиента. После обновления установленной команды также доступно `antizapret-relay preset gemini`. Повторный запуск не дублирует записи. Можно снова открыть мастер и выбрать `1` или `3`: он предложит добавить Gemini, сохранив донора и ключи.

Набор Gemini сохраняет ваши исключения. Если нужный домен или его родительский домен был исключён вручную, удалите соответствующее исключение и примените `parse.sh`.

### 3. Проверьте сайт

Переподключите VPN на телефоне или компьютере и откройте добавленный сайт. VPN-профиль менять не требуется. Если сайт продолжает использовать старый маршрут, очистите DNS-кеш устройства.

## Можно ли быть донором и клиентом одновременно?

Да. В меню выберите **`3` — Both**: VPS будет отдавать свой IP другому серверу и отправлять свои выбранные домены через другого донора. Для этого режима на VPS должен работать AntiZapret.

Мастер сначала установит донорскую роль и спросит **публичный IP этого VPS**, затем для клиентской роли — **IP другого донора**, если готовый файл импорта отсутствует. Если другой донор ещё не готов, нажмите Enter на запросе его IP: пока будет установлена только донорская роль. Когда другой донор готов, снова запустите `bash install.sh` и выберите `1`.

Для взаимного подключения двух новых VPS:

1. На сервере 1 выберите `3`, настройте его донором и отложите клиентскую роль нажатием Enter.
2. На сервере 2 выберите `3`, настройте его донором, а для клиентской роли укажите IP сервера 1.
3. Вернитесь на сервер 1, запустите `bash install.sh`, выберите `1` и укажите IP сервера 2.

Уже установленные роли мастер не переустанавливает, сохраняя ключи и настройки. Для существующего клиента он также предлагает добавить Gemini. Сети выбираются автоматически. Поддерживается один донор для клиентской роли и один клиентский VPS для донорской роли. Один файл подключения нельзя раздавать нескольким VPS.

## Ручная передача настроек

Если root-доступ по SSH с клиента к донору недоступен, передайте файл подключения своим способом. Файл содержит приватные ключи — используйте защищённый канал и не публикуйте его.

Например, **на доноре** отправьте файл клиенту. Вместо `CLIENT_IP` укажите публичный IPv4 VPS с AntiZapret:

```bash
scp /root/antizapret-relay-donor.json root@CLIENT_IP:/root/antizapret-relay-import.json
```

При запросе пароля нужен пароль root **клиентского VPS**. Для нестандартного SSH-порта добавьте `-P НОМЕР_ПОРТА` после `scp`.

Затем **на клиенте** выполните:

```bash
bash install.sh client --bundle /root/antizapret-relay-import.json
```

Мастер `bash install.sh` автоматически использует `/root/antizapret-relay-import.json`, если этот файл есть на клиенте. Собственный файл донора называется `antizapret-relay-donor.json`, полученный от другого — `antizapret-relay-import.json`; это позволяет совмещать обе роли.

## Если не работает

На обоих VPS выполните:

```bash
antizapret-relay status
```

Сначала проверьте, правильно ли указан IP донора и открыт ли его UDP-порт. После открытия сайта с VPN-устройства в статусе туннеля должны появиться `latest handshake` и увеличиваться счётчики передачи.

Доменная маршрутизация требует DNS AntiZapret: сторонний DNS или браузерный DoH могут её обходить. Проверяйте сайт с подключённого VPN-устройства; запрос с самого VPS не проверяет этот маршрут. При недоступном доноре выбранные сайты не откроются — резервного выхода нет.

## Обновление

Выполните **на каждом VPS, где установлен модуль**:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh upgrade
```

Ключи и адреса сохраняются. При первом обновлении клиентской установки до версии `0.3.1` или новее встроенные WARP-домены также будут добавлены в исключения; применение списков кратковременно переподключит WARP-интерфейсы. Следующие обновления сохраняют ваши правки автоматического блока и не возвращают удалённые из него строки. Перед добавлением второй роли обновите старую установку этой командой.

Автоматический блок содержит список, полученный при установке или этом первом обновлении. Если AntiZapret позднее добавит новые встроенные WARP-домены, проверьте их и при необходимости дополните `exclude-warp-hosts.txt` самостоятельно.

## Удаление

На клиентском VPS — отключить использование донора и восстановить прежние параметры WARP:

```bash
antizapret-relay uninstall --role client
```

Модуль также удалит добавленные им автоматические исключения, которые вы оставили без изменений. Ваши прежние исключения и последующие пользовательские записи сохранятся.

Домены Gemini в основном include-файле сохранятся как обычные пользовательские записи; при необходимости удалите их вручную.

На донорском VPS — перестать отдавать свой IP клиенту:

```bash
antizapret-relay uninstall --role server
```

Если на VPS установлены обе роли, каждая удаляется отдельно. Для удаления обеих:

```bash
antizapret-relay uninstall --role all
```

## Дополнительная информация

- По умолчанию выбранные домены идут через донора и в профилях AntiZapret, и в профилях полного VPN. Для изменения только профилей AntiZapret добавьте `--antizapret-only` к команде установки клиента.
- DNS-настройки сохраняются. Донор заменяет выход WARP для трафика выбранных доменов; DNS продолжает работать по настройкам AntiZapret.
- При пересечении адресов с маршрутами клиентского VPS установщик остановится до изменения настроек. Работающий туннель автоматически не перенумеровывается.
- Ежедневные обновления AntiZapret сохраняют настройки. Перед полной переустановкой его `setup.sh` сохраните ключи и удалите клиентскую роль relay.
- Если после установки вручную менять управляемые параметры WARP, перед удалением потребуется согласовать их с резервной копией в `/etc/antizapret-relay`.

<details>
<summary>Дополнительные команды управления доменами</summary>

Команды из прежней инструкции продолжают работать **на клиентском VPS**:

```bash
antizapret-relay domain add example.org
antizapret-relay domain list
antizapret-relay domain remove example.org
```

Они управляют дополнительным файлом `config/relay-include-warp-hosts.txt`, который AntiZapret объединяет со штатными списками. Команда `domain list` показывает только этот дополнительный файл. Добавление и удаление применяются автоматически; штатные исключения действуют и для этих записей. Для обычного использования достаточно редактировать два штатных файла, указанных выше.
