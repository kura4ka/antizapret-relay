# AntiZapret Relay

**AntiZapret Relay** позволяет использовать собственный VPS вместо Cloudflare WARP для маршрутизации выбранных доменов. Трафик идёт через зашифрованный WireGuard-туннель на ваш донорский сервер, а дальше выходит в интернет с его публичного IP.

Проект работает поверх штатной маршрутизации **AntiZapret в режиме Custom**. Он не заменяет AntiZapret и не требует менять VPN-профили на устройствах.

- **Донор (Server)** — VPS, через который выходит выбранный трафик.
- **Клиент (Client)** — VPS с установленным AntiZapret, который направляет выбранные домены через донора.
- **Обе роли (Both)** — один VPS одновременно выступает донором для другого сервера и клиентом для третьего.

Поддерживаются Debian/Ubuntu с systemd и WireGuard. Основные целевые системы — Debian 13 и Ubuntu 24.04.

> Все команды ниже выполняются по SSH от имени `root`. Для перехода в root-shell используйте `sudo -i`.

## Как это работает

1. На донорском VPS устанавливается WireGuard-сервер.
2. На клиентском VPS создаётся WireGuard-подключение к донору.
3. Вы добавляете нужные домены в стандартный список AntiZapret.
4. AntiZapret определяет IP-адреса этих доменов, а Relay направляет соответствующий трафик через WireGuard на донора.
5. Внешние сайты видят публичный IP донорского VPS.

**Важно:** списками доменов управляет сам AntiZapret. Relay не ведёт отдельную копию штатных списков и не требует настраивать домены на донорском сервере.

## Установка

Установщик один и тот же для обеих ролей. Его нужно запустить на каждом VPS отдельно.

Скачайте скрипт:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh
```

### 1. Настройка донора (Server)

Запустите установщик **на VPS, с которого должен выходить трафик**.

В меню выберите:

```text
2 — Server / donor
```

Укажите:

- **Публичный IPv4** донорского VPS.
- **UDP-порт WireGuard**. По умолчанию — `51888`; чтобы оставить его, нажмите Enter.

Откройте выбранный UDP-порт в панели управления хостингом. Правила локального firewall установщик добавит автоматически.

Ключи и параметры туннеля создаются автоматически. После завершения установки донор готов.

> На доноре не нужно добавлять домены в списки AntiZapret.

### 2. Подключение клиента (Client)

Запустите установщик **на VPS, где уже работает AntiZapret**.

В меню выберите:

```text
1 — Client
```

Укажите:

- **Публичный IPv4 донора**.
- **SSH-порт донора** — обычно `22`.

Установщик подключится к донору по SSH и заберёт файл с настройками WireGuard. Для этого используется root-доступ к донорскому VPS. При запросе пароля введите пароль root донора. При использовании SSH-ключа будет применён настроенный ключ.

При первом SSH-подключении проверьте отпечаток ключа сервера.

Если на клиентском VPS уже есть файл `/root/antizapret-relay-import.json`, мастер использует его автоматически и не будет повторно запрашивать IP и SSH-порт донора.

После установки клиентская роль настроит маршрутизацию и применит изменения AntiZapret. Его сервис может быть кратковременно перезапущен.

**Защита встроенных списков:** при установке клиентской роли домены из встроенных `download/*include-warp-hosts.txt` добавляются в специальный блок исключений в `/root/antizapret/config/exclude-warp-hosts.txt`. Это не позволяет автоматически отправить через ваш сервер стандартные домены Cloudflare и STUN/TURN. Существующие пользовательские исключения сохраняются.

Теперь можно переходить к [настройке доменов](#управление-доменами).

### 3. Обе роли на одном VPS (Both)

Режим `Both` позволяет одному VPS одновременно:

- отдавать свой IP другому клиентскому серверу;
- отправлять собственные выбранные домены через другого донора.

Для этого на VPS должен быть установлен и работать AntiZapret.

В меню выберите:

```text
3 — Both
```

Сначала мастер настроит донорскую роль и запросит публичный IP этого VPS. Затем он предложит настроить клиентскую роль и запросит IP другого донора.

**Можно отложить подключение к другому донору:** просто нажмите Enter на запросе его IP. Донорская роль останется установленной. Когда второй сервер будет готов, запустите установщик снова и выберите `1 — Client`.

#### Пример: соединение двух VPS в обе стороны

1. На VPS №1 выберите `3 — Both`, настройте донорскую роль и пропустите клиентскую, нажав Enter.
2. На VPS №2 выберите `3 — Both`, настройте донорскую роль и в качестве донора для клиентской роли укажите VPS №1.
3. Вернитесь на VPS №1, снова запустите установщик, выберите `1 — Client` и укажите VPS №2.

В итоге каждый сервер сможет выступать донором для другого.

Уже установленные роли повторно не переустанавливаются: мастер сохраняет ключи и существующие настройки. Поддерживается один донор для клиентской роли и один клиентский VPS для донорской роли. Один файл подключения нельзя использовать для нескольких клиентов.

## Управление доменами

Домены настраиваются **только на клиентском VPS**, в стандартных файлах AntiZapret.

Основные файлы:

| Файл | Назначение |
|---|---|
| `/root/antizapret/config/include-warp-hosts.txt` | Домены, которые нужно направлять через донора |
| `/root/antizapret/config/exclude-warp-hosts.txt` | Домены, которые нужно исключить из этой маршрутизации |

### Добавить домен

Откройте файл:

```bash
nano /root/antizapret/config/include-warp-hosts.txt
```

Добавьте домены — по одному на строку:

```text
example.com
example.org
```

### Исключить домен

Откройте:

```bash
nano /root/antizapret/config/exclude-warp-hosts.txt
```

Добавьте нужный домен:

```text
direct.example.com
```

### Правила записи доменов

Указывайте домены без:

- `https://` или `http://`;
- путей и параметров URL;
- символов `*`.

Например, правильно: `example.com`.

Запись домена распространяется на сам домен и его поддомены. Исключения имеют приоритет: если домен попал в исключения, одного добавления в include-файл недостаточно.

После изменения списков выполните:

```bash
/root/antizapret/parse.sh
```

Команда заново обработает списки и применит правила маршрутизации. **Перезапускать WireGuard или переподключать WARP вручную обычно не требуется.**

### Как работают штатные списки

AntiZapret учитывает все штатные WARP-списки, включая дополнительные файлы вида `config/*include-warp-hosts.txt`. Исключения из `config/*exclude-warp-hosts.txt` продолжают действовать.

Чтобы направить через донора домен, который попал в автоматически добавленные исключения, удалите соответствующую строку из блока:

```text
ANTIZAPRET RELAY DEFAULT WARP EXCLUSIONS
```

Этот блок находится в `/root/antizapret/config/exclude-warp-hosts.txt`.

Проверьте также, нет ли исключения для родительского домена. Затем примените изменения:

```bash
/root/antizapret/parse.sh
```

Не удаляйте остальные пользовательские исключения без необходимости.

## Gemini

Во время установки клиентской роли мастер предлагает:

```text
Route Gemini through the donor? [y/N]:
```

Ответьте `y`, чтобы добавить подготовленный набор доменов Gemini в штатный список:

```text
/root/antizapret/config/include-warp-hosts.txt
```

Добавить или обновить набор Gemini можно и после установки. На **клиентском VPS** выполните:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh preset gemini
```

Команда добавит недостающие домены без переустановки клиента. Существующие записи не дублируются, настройки донора и ключи не меняются.

В установленной версии также доступна короткая команда:

```bash
antizapret-relay preset gemini
```

Если нужный домен Gemini или его родительский домен находится в исключениях, удалите соответствующее исключение и выполните `/root/antizapret/parse.sh`.

## Проверка работы

На клиентском и донорском VPS выполните:

```bash
antizapret-relay status
```

Проверьте, что:

- WireGuard-интерфейс поднят;
- отображается свежий `latest handshake`;
- счётчики переданных данных увеличиваются при обращении к выбранному сайту.

Затем подключите VPN на телефоне или компьютере и откройте домен, который добавили в include-файл.

**VPN-профиль на устройстве менять не нужно.**

Если сайт продолжает открываться по старому маршруту, очистите DNS-кеш устройства и проверьте настройки DNS. Для доменной маршрутизации требуется DNS AntiZapret: сторонний DNS или DoH в браузере могут обойти его правила.

Запрос с самого VPS не является полноценной проверкой маршрута клиентского устройства.

> Резервного маршрута через обычный WARP при недоступности донора нет. Если донор или туннель недоступен, выбранные домены могут перестать открываться.

## Обновление Relay

Обновлять модуль нужно **на каждом VPS**, где он установлен.

Выполните:

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
bash install.sh upgrade
```

Обновление сохраняет ключи, адреса и настройки ролей.

При первом обновлении клиентской установки до версии `0.3.1` или новее встроенные WARP-домены AntiZapret также добавляются в автоматический блок исключений и применяются через `parse.sh`.

В версии `0.3.4` исправлено восстановление защиты Relay после перезапуска AntiZapret: правила Relay снова устанавливаются выше штатных разрешающих правил. Одновременные вызовы firewall для клиентской и донорской ролей выполняются последовательно.

Изменения автоматического блока исключений сохраняются при следующих обновлениях. Если вы вручную удалили из него строку, Relay не должен добавлять её обратно при каждом обновлении.

**Обновление Relay само по себе не означает переподключение WARP.** В актуальном AntiZapret переподключение при обработке списков зависит от параметра `RECONNECT_WARP=y` в `/root/antizapret/setup`. Если параметр не включён, обновление списков не должно принудительно переподключать WARP.

## Обновление AntiZapret

Обычное обновление списков AntiZapret через `doall.sh` не требует удаления Relay. Но **полное обновление AntiZapret с запуском нового upstream `setup.sh` — отдельная процедура**: установщик AntiZapret может изменить настройки WARP и WireGuard.

В частности, переход на новую реализацию fake IP требует полного upstream `setup.sh`. Он сбрасывает настройки удалённых WARP peers и может перезагрузить VPS.

Перед таким обновлением выполните следующие действия.

### Перед обновлением

Сохраните резервные копии **вне каталога `/root/antizapret`**:

- `/etc/antizapret-relay`;
- `/root/antizapret/config`;
- файл подключения к донору — `/root/antizapret-relay-import.json`.

Если файла импорта нет, получите его повторно с донора: `/root/antizapret-relay-donor.json`.

Файлы подключения содержат приватные ключи. Храните резервные копии с доступом только для root и не передавайте их через публичные каналы.

### Порядок обновления

1. **На клиентском VPS** удалите клиентскую роль Relay, сохранив предварительно резервные копии:

   ```bash
   antizapret-relay uninstall --role client
   ```

2. Если на этом же VPS установлена донорская роль, дополнительно сохраните её конфигурацию:

   ```bash
   cp /etc/wireguard/az-relay.conf /root/az-relay.conf.backup
   ```

   Остановите донорский туннель на время обновления:

   ```bash
   systemctl disable --now wg-quick@az-relay.service
   ```

   Удалять донорскую роль не нужно. Установщик AntiZapret может массово менять адреса `10.*` и `172.*` в WireGuard-конфигах, поэтому важно сохранить исходный конфиг донора.

3. Обновите AntiZapret по его штатной инструкции и дождитесь перезагрузки, если она потребуется.

4. Убедитесь, что AntiZapret запущен. Если на VPS есть донорская роль, восстановите сохранённый конфиг:

   ```bash
   install -m 600 /root/az-relay.conf.backup /etc/wireguard/az-relay.conf
   systemctl enable --now wg-quick@az-relay.service
   ```

5. **На клиентском VPS** установите клиентскую роль заново из сохранённого файла подключения:

   ```bash
   curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
   bash install.sh client --bundle /root/antizapret-relay-import.json
   ```

   Либо запустите мастер и выберите `1 — Client`, чтобы повторно получить настройки с прежнего донора.

6. Проверьте списки доменов и состояние туннеля:

   ```bash
   antizapret-relay status
   ```

Резервная копия `/etc/antizapret-relay` нужна для восстановления при ошибке. **Не копируйте её поверх новой установки без необходимости**: после успешной переустановки клиента это может вернуть старое состояние.

## Ручная передача настроек

Обычно клиент получает параметры подключения с донора автоматически по SSH. Если root-доступ по SSH недоступен, файл можно передать вручную.

Файл содержит приватные ключи — используйте только защищённый канал передачи.

Например, на доноре выполните команду, заменив `CLIENT_IP` на публичный IPv4 клиентского VPS:

```bash
scp /root/antizapret-relay-donor.json root@CLIENT_IP:/root/antizapret-relay-import.json
```

Если у клиента нестандартный SSH-порт, добавьте параметр `-P`:

```bash
scp -P 2222 /root/antizapret-relay-donor.json root@CLIENT_IP:/root/antizapret-relay-import.json
```

Затем на клиенте запустите установку:

```bash
bash install.sh client --bundle /root/antizapret-relay-import.json
```

Назначение файлов:

- `antizapret-relay-donor.json` — файл с настройками собственной донорской роли.
- `antizapret-relay-import.json` — файл, полученный от другого донора для клиентской роли.

Разные имена позволяют использовать обе роли на одном VPS.

## Удаление

Роли удаляются независимо друг от друга.

**Удалить клиентскую роль** — перестать направлять выбранные домены через донора и восстановить прежние параметры WARP:

```bash
antizapret-relay uninstall --role client
```

Модуль удалит добавленные им автоматические исключения, которые остались без изменений. Старые пользовательские исключения и новые пользовательские записи сохранятся.

Домены Gemini, добавленные в основной include-файл, останутся там как обычные записи. При необходимости удалите их вручную.

**Удалить донорскую роль** — перестать предоставлять свой IP клиенту:

```bash
antizapret-relay uninstall --role server
```

**Удалить обе роли:**

```bash
antizapret-relay uninstall --role all
```

Если на VPS установлены обе роли, удаление только одной не затронет другую.

## Дополнительные команды и ограничения

### Команды для управления доменами

На клиентском VPS доступны команды для управления дополнительным списком Relay:

```bash
antizapret-relay domain add example.org
antizapret-relay domain list
antizapret-relay domain remove example.org
```

Они работают с файлом:

```text
/root/antizapret/config/relay-include-warp-hosts.txt
```

AntiZapret объединяет его со штатными списками. Команда `domain list` показывает только этот дополнительный файл. Для обычной настройки рекомендуется использовать стандартные `include-warp-hosts.txt` и `exclude-warp-hosts.txt`.

### Дополнительные параметры

- По умолчанию выбранные домены направляются через донора как в профилях AntiZapret, так и в профилях полного VPN.
- Чтобы ограничить маршрутизацию только профилями AntiZapret, добавьте `--antizapret-only` при установке клиентской роли.
- DNS-настройки AntiZapret сохраняются. Донор меняет выходной маршрут выбранного трафика, но не заменяет DNS.
- Если адресная подсеть туннеля пересекается с уже используемыми маршрутами клиентского VPS, установщик остановится до изменения настроек. Работающий туннель автоматически не перенумеровывается.
- Если после установки вы вручную изменяли параметры WARP, перед удалением Relay может потребоваться сверить их с резервной копией в `/etc/antizapret-relay`.

### Установка без меню

Можно выбрать роль прямо в командной строке.

На доноре:

```bash
bash install.sh server --endpoint DONOR_IP --port 51888
```

На клиенте, когда файл настроек уже передан:

```bash
bash install.sh client --bundle /root/antizapret-relay-import.json
```

Чтобы при установке клиента сразу добавить набор Gemini:

```bash
bash install.sh client --bundle /root/antizapret-relay-import.json --gemini
```

## Совместимость и проверка

Совместимость исходников проверена с обновлением AntiZapret [`314f5a1`](https://github.com/GubernievS/AntiZapret-VPN/commit/314f5a105bca9111ed2ab62a782f497ac0bbeeec): fake IP перешли на nftables, при этом используемые Relay параметры WARP, интерфейсы и таблицы маршрутизации сохранены.

Это проверка совместимости исходников, а не гарантия доступности туннеля на конкретном VPS. После обновления проверяйте состояние командой `antizapret-relay status` и тестируйте доступ к выбранным сайтам с подключённого устройства.

Подробности устройства проекта, технические ограничения и проверенный upstream-коммит описаны в [документе по архитектуре](docs/architecture.md).
