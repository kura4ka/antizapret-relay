# AntiZapret Relay

Отправляет выбранные домены через другой VPS вместо Cloudflare WARP. Использует штатные списки и маршрутизацию [AntiZapret-VPN](https://github.com/GubernievS/AntiZapret-VPN). Клиентские VPN-профили менять не нужно.

## Кто донор, кто клиент

| Роль VPS | Что он делает | Команда установки |
| --- | --- | --- |
| **Клиент — сервер 1** | К нему подключаются ваши VPN-пользователи. На нём добавляются домены. | `client` |
| **Донор — сервер 2** | Выпускает выбранный трафик в Интернет через свой IP. | `server` |

```text
VPN-пользователь → Клиент (сервер 1) → WireGuard → Донор (сервер 2) → выбранный сайт
                                   ↘ остальные сайты — по настройкам AntiZapret
```

VPS могут находиться в любых странах и у любых хостеров. Один VPS может одновременно быть **донором и клиентом**. Подсеть туннеля, адреса и ключи установщик создаёт автоматически с проверкой занятых маршрутов. Вручную настраивать сети не требуется.

**Что подготовить:** публичные IPv4 обоих VPS, SSH-доступ и свободный UDP-порт на доноре. По умолчанию порт — **51888**. На клиенте должен быть установлен и запущен AntiZapret; на доноре AntiZapret необязателен. Требуются Debian/Ubuntu, systemd и WireGuard в ядре; целевые версии — Debian 13 и Ubuntu 24.04.

Все команды ниже выполняются в SSH-сессии под **root**. Если вы вошли обычным пользователем, сначала выполните `sudo -i`.

## На доноре

Это **сервер 2**, через IP которого должны открываться выбранные сайты.

**1. Скачайте установщик:**

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
```

**2. Укажите публичный IP этого донорского VPS:**

```bash
bash install.sh server --endpoint DONOR_IP --port 51888
```

Замените **`DONOR_IP`** на публичный IPv4 донора — того VPS, IP которого должны видеть выбранные сайты. Номер порта можно поменять; выбранный **UDP-порт** нужно открыть в firewall панели хостинга. Локальные правила Linux установщик добавит сам.

Скрипт выберет свободную туннельную подсеть, создаст ключи и запустит WireGuard. Готовый файл подключения появится здесь:

```text
/root/antizapret-relay-donor.json
```

**3. Передайте файл подключения клиентскому VPS:**

Всё ещё **на доноре** выполните:

```bash
scp /root/antizapret-relay-donor.json root@CLIENT_IP:/root/antizapret-relay-import.json
```

Замените **`CLIENT_IP`** на публичный IPv4 **сервера 1**, к которому подключаются ваши VPN-пользователи. Это адрес получателя файла. Если SSH клиента работает на другом порту, добавьте `-P НОМЕР_ПОРТА` сразу после `scp`.

Файл содержит приватные ключи. Передавайте его через SSH; не публикуйте в GitHub. На клиенте он сохраняется под другим именем — `antizapret-relay-import.json`, чтобы не перезаписать собственный файл донора при совмещении ролей.

## На клиенте

Это **сервер 1** с работающим AntiZapret. Перейдите в его SSH-сессию.

**1. Скачайте тот же установщик:**

```bash
curl -fSL https://raw.githubusercontent.com/kura4ka/antizapret-relay/main/install.sh -o install.sh
```

**2. Подключите донора и добавьте первый домен:**

```bash
bash install.sh client \
  --bundle /root/antizapret-relay-import.json \
  --domain old.yummyani.me
```

Замените **`old.yummyani.me`** на нужный домен либо оставьте его для этого примера. IP, порт и ключи донора уже находятся в JSON — повторно вводить их на клиенте не нужно. Несколько доменов можно передать повторением `--domain`:

```bash
bash install.sh client --bundle /root/antizapret-relay-import.json \
  --domain example.com --domain video.example.net
```

Запускайте **одну** из этих команд установки. AntiZapret кратковременно перезапустится; активные соединения могут прерваться. После установки переподключите VPN на устройстве.

По умолчанию донор используется для выбранных доменов как в профилях AntiZapret, так и в профилях полного VPN. Чтобы подключить донора только для профилей AntiZapret, добавьте `--antizapret-only` к команде установки.

**3. В дальнейшем управляйте доменами на клиенте:**

```bash
antizapret-relay domain add example.com
antizapret-relay domain list
antizapret-relay domain remove example.com
```

Домен включает его поддомены. Изменения применяются автоматически; если устройство сохранило старый DNS-ответ, очистите его DNS-кеш или переподключите VPN. Доменов у видео, картинок и авторизации может быть несколько — при необходимости добавьте их тоже.

## Донор и клиент одновременно на одном VPS

Обе роли можно устанавливать в любом порядке. Уже установленная роль, её ключи и адреса сохраняются. Например, сервер 1 может отдавать свой IP серверу 2 и одновременно отправлять свои выбранные домены через сервер 2.

Для взаимного подключения:

1. Выполните раздел **«На доноре» на каждом VPS**. В `--endpoint` каждый раз указывайте публичный IP того VPS, на котором сейчас выполняете команду.
2. Каждый донор передаёт свой `antizapret-relay-donor.json` **на другой VPS** под именем `antizapret-relay-import.json`.
3. Выполните раздел **«На клиенте» на каждом VPS**, используя полученный с другого VPS файл. Списки доменов на серверах независимы.

Подсети подбираются автоматически. На входе проверяется также пересечение с маршрутами клиента; при конфликте установка останавливается до изменения настроек. Трафик, полученный от другого VPS, выходит через обычное внешнее подключение донора и повторно в клиентский туннель relay не отправляется.

Сейчас на одном VPS поддерживается **одна клиентская роль к одному донору** и **одна донорская роль для одного другого VPS**. Несколько клиентских VPS не должны использовать один и тот же JSON: в нём фиксированные ключи и адреса.

## Проверка

**На клиенте и на доноре:**

```bash
antizapret-relay status
```

Если установлены обе роли, команда показывает обе.

**На клиенте:**

```bash
wg show warp-antizapret
wg show warp-vpn
```

Endpoint должен указывать на IP и порт донора. **На доноре:**

```bash
wg show az-relay
```

Проверьте недавний `latest handshake` и увеличение счётчиков передачи после открытия выбранного сайта **с подключённого VPN-устройства**. Наличие интерфейса само по себе не подтверждает связь. Запрос с самого VPS не проверяет доменную маршрутизацию VPN-пользователя.

Если связи нет, сначала проверьте публичный IP донора и открытый UDP-порт в панели хостинга. Для проверки маршрутов **на клиенте**:

```bash
ip -4 route show table 1000
ip -4 route show table 2000
```

Ожидаются `default dev warp-antizapret` и `default dev warp-vpn`. С `--antizapret-only` модуль управляет только первым интерфейсом.

## Обновление и удаление

**На VPS, где модуль уже установлен**, скачайте свежий `install.sh` и выполните:

```bash
bash install.sh upgrade
```

Обновляются установленный скрипт и служебные hooks. Существующие ключи и туннельные адреса сохраняются; туннели не перезапускаются. Это также подготавливает старую версию модуля к добавлению второй роли.

**На нужном VPS** можно удалить только одну роль:

```bash
antizapret-relay uninstall --role client
antizapret-relay uninstall --role server
```

Первая команда отключает клиентскую роль и восстанавливает прежние параметры WARP. Вторая отключает донора. Другая роль сохраняется. Для удаления обеих:

```bash
antizapret-relay uninstall --role all
```

Если установлена только одна роль, достаточно `antizapret-relay uninstall`. При двух ролях команда без указания роли попросит выбрать её.

## Что сохраняется от AntiZapret

- Используются штатные fake IP, DNS и маршрутизация доменов. Основной маршрут VPS и SSH модуль не меняет.
- Это замена выхода WARP: через донора пойдёт **вся штатная группа WARP**, включая записи из других include-файлов. Штатные exclude-файлы продолжают работать.
- Собственный список: `/root/antizapret/config/relay-include-warp-hosts.txt`. Удаление домена из него не удаляет тот же домен из других списков.
- DNS-настройки и IPv6-поведение остаются штатными. На устройствах нужен DNS AntiZapret; браузерный DoH может обойти выбор домена.
- При недоступном доноре выбранные сайты перестают открываться. Автоматического резервного выхода нет; защита запрещает помеченному трафику выход через другой интерфейс.
- Донор разрешает только выход в публичный IPv4 Интернет, ограничивает доступ к своей локальной сети и самому VPS. Запреты AntiZapret в таблице `raw` сохраняются.
- Ежедневные обновления AntiZapret сохраняют настройки. Полная переустановка его `setup.sh` пересоздаёт конфигурацию; перед ней сохраните ключи и удалите клиентскую роль relay.

При удалении восстанавливаются только управляемые параметры WARP; остальные настройки AntiZapret сохраняются. Если вы вручную изменили управляемые параметры после установки, восстановление остановится, сохранив резервную копию в `/etc/antizapret-relay`.

## Разработка и проверки

```bash
python3 tools/build.py
python3 -m unittest discover -s tests -v
bash -n install.sh
shellcheck -S warning install.sh
```

`install.sh` автономный; исходники находятся в `lib/`. Проверки покрывают конфигурацию, подбор подсетей, изоляцию ролей, откат и правила firewall через подставные системные команды. Linux CI запускает их на GitHub. Это не заменяет испытание на реальной паре VPS; такое испытание ещё требуется.

Подробности интеграции: [docs/architecture.md](docs/architecture.md).
